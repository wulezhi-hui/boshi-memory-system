## 三、双轨接入详解

### 3.1 插件方式（Hermes MemoryProvider）★ v6.2 新增

- **文件**：`plugins/boshi/__init__.py` → 复制到 `$HERMES_HOME/plugins/boshi/`
- **激活**：`config.yaml` → `memory.provider: boshi`
- **机制**：实现 `agent/memory_provider.py` 的 `MemoryProvider` ABC，由 Hermes MemoryManager 生命周期驱动：

| 生命周期 | 行为 |
|:-----|:-----|
| `system_prompt_block()` | 注入记忆库状态 + 用户画像热区（会话组装一次） |
| `queue_prefetch()` / `prefetch()` | 每轮后台召回 bge-m3 语义 + 图谱融合，注入上下文 |
| `sync_turn()` | 每轮对话后自动把用户消息存入记忆库 |
| `on_memory_write()` | 镜像：内置 memory 工具写入时同步存伯仕 |
| `on_pre_compress()` | 压缩前保存即将丢弃的对话 |
| `backup_paths()` | 声明 chroma_db/ 纳入 `hermes backup` |

- **与 MCP 的关系**：可同时启用。插件负责"被动自动"（每轮注入），MCP 负责"主动调用"（agent 按需搜索/管理）。

### 3.2 MCP 方式（8 工具）

| 工具 | 作用 |
|:-----|:-----|
| `boshi_search` | 语义 + FTS5 混合检索 |
| `boshi_save` | 存储记忆 |
| `boshi_delete` | 删除记忆 |
| `boshi_status` | 记忆库状态 |
| `boshi_profile` | 用户画像 |
| `boshi_graph` | 知识图谱查询 |
| `boshi_graph_add` | 图谱添加节点/关系 |
| `boshi_recent` | 最近 N 条记忆 |

## 四、向量层（bge-m3 ONNX）★ v6.2 升级

| 项 | v6.1 | v6.2 |
|:-----|:-----|:-----|
| 模型 | SentenceTransformer MiniLM-L12-v2 | **BAAI/bge-m3（Xenova ONNX 导出）** |
| 维度 | 384 | **1024** |
| 文件 | 外部依赖 | `~/.boshi/models/bge-m3/onnx/model_quantized.onnx`（int8 ~569MB） |
| 推理 | sentence-transformers | onnxruntime CPU（零外网依赖） |
| 空间 | L2 | **cosine** |
| 下载 | 无 | `python download_model.py`（hf-mirror 国内镜像，断点续传） |

- `onnx_embed.py`：onnxruntime + transformers tokenizer 推理封装；`model_quantized.onnx` 优先，`model.onnx`（fp32）回退
- `chroma_bridge.py` 通过 `get_embedding_function()` 统一取 embedding，MCP/CLI/插件共享

## 六、部署与安装

### 6.1 一键安装（其它人可直接使用）

```bash
# Linux / macOS（自动下载 bge-m3 模型，默认 hf-mirror 国内镜像）
curl -sL https://raw.githubusercontent.com/wulezhi-hui/boshi-memory-system/main/install.sh | bash

# Windows
git clone https://github.com/wulezhi-hui/boshi-memory-system.git %USERPROFILE%\.boshi
python %USERPROFILE%\.boshi\install.py
```

安装内容：部署代码 → 安装依赖（chromadb/mcp>=2.0/onnxruntime/transformers）→ 下载模型 → 复制插件 → 写双轨配置 → 安装 skill。

## 七、知识图谱（★ 2026-08-19 完善激活）

### 7.1 背景

知识图谱功能代码自 v5.0 存在，但长期**未激活**：`KnowledgeGraph` 类从未实现 → `boshi_core._get_kg()` 一直 ImportError → `status()` 的 `except: pass` 吞错显示 0 → 图谱恒为空。2026-08-19 修复并完善。

### 7.2 核心能力

| 能力 | 函数/类 | 说明 |
|------|---------|------|
| **图谱召回** | `KnowledgeGraph.search(query)` | 按查询词匹配实体，`_graph_search` 依赖（缺失时三路融合 graph=0） |
| **动态实体学习** | `KnowledgeGraph.learn_entities(text)` | 自动发现新实体并扩展 KNOWN_ENTITIES（英文大写词/《书名号》/中文"XX系统"）；噪音过滤 `_COMMON_EN_WORDS` + `_KEEP_ACRONYMS` |
| **边类型区分** | `auto_link_entities()` | 按上下文线索词：derives(依赖/使用)/updates(升级)/extends(扩展)/related(共同出现) |
| **O(1) 去重** | 模块级 `_EDGE_CACHE` | 修复原 `get_relations(top_k=50)` 边多时去重失效 |
| **精确统计** | `get_all_relations()` | chroma_bridge 新增，col.get 精确查询（不走语义搜索避免误匹配） |
| **save() 联动** | `boshi_core.save()` | 每次存记忆自动调 auto_link_entities 建边（失败不阻断） |

### 7.3 数据流

```
save(记忆) → ChromaDB 存储 → auto_link_entities(内容)
  → learn_entities(发现新实体) → extract_entities(匹配已知+新实体)
  → 实体≥2 → 按线索词判断边类型 → add_relation 建边
  → _EDGE_CACHE 去重（O(1)）

检索：search() → hybrid(语义+全文) + graph(图谱召回) 三路融合
```

### 7.4 已知限制

- 历史回填数据含少量噪音实体（从代码/边文本学到，如 ImportError）；日常 save() 走对话内容不再产生
- CPU/GPU/API 等技术缩写作为合法实体保留
- `_KEEP_ACRONYMS`/`_COMMON_EN_WORDS` 白名单需随使用持续补充

## 八、已知注意点

- 路径统一 `~/.boshi`（不再硬编码 Administrator）
- 实体提取默认走 Ollama LLM，对话中请用 `extract_facts_async`（后台线程 + 15s 超时）避免阻塞
- 检索优先 FTS5（trigram 中文 MATCH），失败自动降级 LIKE
- 插件方式依赖 Hermes `agent/memory_provider.py` 的 `MemoryProvider` ABC（Hermes v6.2+ 原生支持，无需 run_agent.py 补丁）
- Hermes 升级可能覆盖 `mcp_tool.py` 的 isError 兼容补丁（见 docs/Hermes集成技术手册.md §7.1）
